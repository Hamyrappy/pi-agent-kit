# Pi Agent Kit

Личный Telegram-ассистент на [Pi](https://github.com/earendil-works/pi).
Два переключаемых лица — ассистент и инженер — используют общую память
в обычных Markdown-файлах. Папку можно открыть в Obsidian.

Нужны Node.js **22.19+**, npm и отдельный Telegram-бот от
[@BotFather](https://t.me/BotFather). Запускайте комплект под отдельным
обычным пользователем: Pi умеет читать файлы, менять их и выполнять команды
с правами этого пользователя. Это рабочий агент, а не изолированная песочница.

## Первый запуск

```bash
git clone https://github.com/Hamyrappy/pi-agent-kit.git
cd pi-agent-kit
npm ci --ignore-scripts
npm run init
npm run login
```

`init` спросит токен бота, ваш числовой **user ID** (не username и не ID бота),
папку памяти и необязательные provider/model. Свой ID можно получить у
[@userinfobot](https://t.me/userinfobot). Токен вводится в видимом терминале;
не делитесь записью терминала. Комплект принимает сообщения только от ID
из `telegram.allowedUserIds` в личном чате.

`npm run login` открывает интерактивный Pi. Выполните **`/login`**, выберите
провайдера и пройдите авторизацию. Затем **`/model`** для выбора модели.
Для ChatGPT выберите доступный в Pi способ входа OpenAI Codex/ChatGPT
(`openai-codex`); возможность использования зависит от аккаунта и провайдера.
API-ключи и OAuth подписки настраиваются средствами Pi, подписка не нужна
для провайдеров с API-ключом. Выйдите из Pi через Ctrl+C.

```bash
npm run doctor
npm start
```

Откройте личный чат с ботом, отправьте `/start`, затем обычное сообщение.
`doctor` проверяет локальную настройку без запросов к Telegram и модели;
первый ответ бота проверяет реальный доступ к выбранной модели.

**Одна папка авторизации:** `npm run login` и `npm start` используют
`PI_CODING_AGENT_DIR=<папка-комплекта>/.pi-agent`. Если переопределяете эту
переменную, задавайте одинаковое значение для входа и запуска.
Не выполняйте отдельный глобальный `pi /login`: он может сохранить вход
в другую папку. Утилита `npm run login -- --...` не передаёт аргументы Pi;
выбор выполняется командами внутри Pi или через `config.json`.

## OpenRouter и другие модели

Вместо OAuth можно добавить ключ в локальный `.env`:

```dotenv
OPENROUTER_API_KEY=ваш-ключ
```

В `config.json` укажите оба поля в существующем объекте `pi`, сохранив
`command` и `args`, которые создал init:

```json
{
  "provider": "openrouter",
  "model": "deepseek/deepseek-v4.1-flash"
}
```

Если меняли config вручную, выполните `npm run model:configure`: для выбранной
модели OpenRouter он добавляет лимит ответа 8192 tokens в локальный Pi
`models.json`. Init делает это автоматически. Существующий пользовательский
лимит сохраняется; это лимит ответа, а не ограничение расходов аккаунта.

Название модели проверяйте в каталоге своего провайдера: доступность и цена
меняются. Для другого провайдера используйте его ID и переменную API key,
описанную в [документации Pi](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/providers.md).
Можно оставить provider/model пустыми при init и выбирать через Pi `/model`.
Явные поля `pi.provider` и `pi.model` в config имеют приоритет при запуске бота.

## Лица и память

После init папка `vault/` содержит:

```text
AGENTS.md                  общие правила и границы инициативы
memory.md                  общие факты и предпочтения
onboarding.md              цели, знакомство, идеи автоматизаций
faces/assistant/AGENTS.md   помощь с делами и планами
faces/engineer/AGENTS.md    код, отладка, инструменты
```

Ассистент постепенно узнаёт ваши задачи, записывает подтверждённые
предпочтения и предлагает полезные автоматизации. Это инструкции для модели;
качество и инициативность зависят от выбранной модели. Перед внешними
действиями общие правила требуют поручения пользователя.

Можно указать существующую папку Obsidian при init: добавляются только
отсутствующие файлы шаблона, существующие заметки не перезаписываются.
Настройку папки можно изменить в `config.json` (`vaultRoot`).
Для нового лица создайте `faces/<имя>/AGENTS.md`.
Память общая, история диалога ведётся отдельно для каждого лица.
Команды и доступные лица показаны в `/help`.

## Групповые чаты

По умолчанию группы выключены. Чтобы разрешить конкретную группу, добавьте
её числовой ID в `telegram.allowedChatIds` в config и перезапустите бот.
В разрешённой группе он отвечает на упоминание `@имя_бота` или ответ на своё
сообщение. Обычным участникам он отвечает без инструментов, MCP и расширений.
Владелец может поручать действия и использовать управляющие команды.
Общая память входит в контекст группы, поэтому не подключайте чужие группы
к ассистенту с личной памятью.

## Напоминания и отложенная работа

Бот проверяет `.state/jobs/` каждые пять секунд. Одноразовое задание —
JSON-файл с уникальным именем, например `meeting-01.json`:

```json
{"dueAt":"2026-12-01T12:00:00Z","chatId":123456,"prompt":"Напомни о встрече","face":"assistant"}
```

Подставьте своё время с часовым поясом и разрешённый chat ID. Можно попросить
ассистента создать такое задание; инструкции шаблона описывают механизм.
Бот должен работать в момент выполнения. После перезапуска просроченные
задания запускаются при следующей проверке. Задания переносятся в `done/`
или `failed/`; повторяющееся расписание автоматически не создаётся.
`PI_KIT_STATE_DIR` передаёт агенту актуальный путь к состоянию.

## Фоновый запуск в Linux

Сначала убедитесь, что бот отвечает при `npm start`, остановите его Ctrl+C:

```bash
npm run service:install
systemctl --user status pi-agent-kit
journalctl --user -u pi-agent-kit -f
```

Установщик создаёт и запускает user unit с абсолютным путём Node.
Для работы после выхода пользователя может потребоваться
`loginctl enable-linger "$USER"`. Остановка:
`systemctl --user disable --now pi-agent-kit`.
После переноса папки или смены Node заново выполните init/обновите абсолютные
`pi.command`, `pi.args` в config и переустановите unit.
Не запускайте одновременно два экземпляра одного Telegram-бота.

## Возможности первой версии

В Telegram поддерживается текст. Голосовые сообщения, вложения, готовые
интеграции календаря и трекеров пока не подключены. Их можно добавлять
через инструменты и расширения Pi. После аварии незавершённая задача
может выполниться повторно, поэтому внешние действия требуют проверки.

## Локальные данные и диагностика

- `.env` — Telegram token и API keys; `config.json` — пути и разрешённые ID.
- `.pi-agent/` — OAuth/API-авторизация и настройки Pi.
- `.state/` — состояние и история; `vault/` — личная Markdown-память.

Эти пути исключены из Git. OAuth и токены не входят в шаблон и не нужны
другим пользователям: каждый проходит собственный вход. При внешней папке
памяти настройте её резервное копирование отдельно. Не публикуйте историю
диалогов: в ней могут быть личные сведения.

Если бот молчит: проверьте `npm run doctor`, user ID и логи. Ошибка Telegram
409 обычно означает, что уже запущен другой polling-процесс или webhook.
Ошибка авторизации модели: повторите `npm run login`, проверьте выбранные
provider/model и совпадение `PI_CODING_AGENT_DIR`. Авторизация другого
провайдера сама по себе не даёт доступ к выбранной модели.

Для разработки: `npm test`. Зависимость Pi зафиксирована в package-lock.json;
обычная установка: `npm ci --ignore-scripts`. Обновляйте её осознанно вместе
с lockfile и тестами. Лицензия MIT.
