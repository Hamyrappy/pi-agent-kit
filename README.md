# Pi Agent Kit

Личный Telegram-помощник с памятью в Markdown и доступом к своему серверу.
Можно подарить другу: получателю не нужны GitHub, программирование или подписка
ChatGPT. Нужны небольшой сервер с Ubuntu/Debian, Telegram-бот и оплаченный
ключ [OpenRouter](https://openrouter.ai/keys). Код открыт и доступен самому
помощнику для доработки. Основа — [Pi](https://github.com/earendil-works/pi).

## Подарить и установить

Подготовьте чистый сервер Ubuntu 24.04 / Debian 12 или новее, x86_64 либо arm64,
с systemd, доступом в интернет и примерно 1 ГБ RAM (2 ГБ удобнее для обновлений).
Можно установить от root или пользователя с sudo. Получателю нужны:

1. Свой бот от [@BotFather](https://t.me/BotFather): команда `/newbot`, затем токен.
2. Свой числовой Telegram **user ID** от [@userinfobot](https://t.me/userinfobot).
3. Свой OpenRouter API key с доступным балансом. Лимиты расходов задаются в OpenRouter.

На сервере выполните одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/Hamyrappy/pi-agent-kit/main/install.sh | sudo bash
```

Установщик спросит токен, user ID, API key, имя помощника и часовой пояс IANA
(например, `Europe/Moscow`). Токен и ключ вводятся скрыто через терминал.
Он проверит токен в Telegram, установит Node.js 22+, зависимости из lockfile,
создаст отдельного пользователя и systemd-службу. GitHub-аккаунт не нужен.
После завершения откройте чат с ботом и отправьте `/start`.

Установщик не обновляет пакеты всей ОС. При повторном запуске существующая
папка не перезаписывается. Если установка прервалась, сообщение покажет команду
продолжения. Каждый получатель использует свои ключи и личную память.
Не передавайте ему `.env`, авторизацию или заметки другого пользователя.

## Получателю

Пишите как человеку: «помоги разобрать задачи», «запомни, что я…», «напомни завтра
в 10», «найди информацию и сохрани вывод». Можно присылать голосовые сообщения,
аудио, фотографии и файлы до 20 МБ. Голос расшифровывается через OpenRouter;
PDF и DOCX извлекаются локально. Помощник может создавать файлы, выполнять
команды на сервере и менять собственный код. Код и память принадлежат вам.
Это права отдельного пользователя Linux; доступы к другим сервисам появляются,
когда вы их настроите.

Помощник постепенно знакомится с вами, сохраняет подтверждённые предпочтения
и предлагает полезные действия. `/help` показывает команды, `/face` переключает
ассистента и инженера. У них общая память и отдельные истории диалога.
Напоминания выполняются, пока сервер и бот работают; просроченные задания
подхватываются после перезапуска. Качество ответов зависит от модели.

По умолчанию бот отвечает только вашему ID в личном чате. Для групп добавьте
конкретные ID в `telegram.allowedChatIds` в `config.json` и перезапустите службу.
В разрешённой группе бот отвечает на упоминание или ответ на своё сообщение;
участникам, кроме владельца, инструменты недоступны. Общая память попадает
в контекст группы — учитывайте это при подключении личного помощника к группе.

### Форматирование ответов

Ответы Pi отправляются в Telegram как HTML (`parse_mode: HTML`): заголовки и
`**жирный**` становятся `<b>`, списки — маркерами, цитаты — `blockquote`,
таблицы уплощаются в строки `a · b`, блоки кода — `<pre>`. Если Telegram
отклонит разметку, тот же фрагмент повторно уходит простым текстом, поэтому
ответ не теряется. Текст без разметки по-прежнему уходит без `parse_mode`.

## Память и настройки

Установка лежит в `/opt/pi-agent-kit`, исходники доступны пользователю
`pi-agent-kit` для записи. Внутри:

- `vault/` — обычные Markdown-файлы: правила, память, знакомство и лица;
- `config.json` — разрешённые ID, модель, пути и часовой пояс;
- `.env` — токен Telegram и API key;
- `.pi-agent/` — локальная авторизация Pi;
- `.state/` — диалоги, вложения и отложенные задания.

`vault/` можно открыть в Obsidian или синхронизировать отдельно. Для существующей
папки задайте абсолютный `vaultRoot` в config и обеспечьте пользователю службы
доступ к ней. Обновление не заменяет вашу память шаблоном. Для нового лица
добавьте `vault/faces/<имя>/AGENTS.md`.

Смена модели: измените `pi.provider` и `pi.model` в config, сохраняя `command`
и `args`, затем выполните `npm run model:configure` от пользователя службы
и перезапустите бот. При установке собственного Node добавьте его в PATH:
`export PATH=/opt/pi-kit-node/bin:$PATH`. По умолчанию используется OpenRouter
`deepseek/deepseek-v4.1-flash`; проверьте доступность в своём аккаунте.
Для нового OpenRouter-моделя configure задаёт лимит ответа 8192 токенов,
сохраняя пользовательский лимит. Это не лимит расходов аккаунта.
Можно использовать другие провайдеры, которые поддерживает Pi.

## Резервные копии, обновление и откат

Ежедневный systemd-таймер сохраняет `/var/backups/pi-agent-kit/latest.tar.gz`
и до трёх предыдущих снимков. Копия содержит исходники, секреты, состояние
и всю настроенную папку памяти, включая внешнюю; `node_modules` и `.git`
исключены. Копии приватны для root. Это копия на том же сервере: для защиты
от его потери перенесите архивы на другой носитель или машину.
На время снимка работающий бот останавливается, затем запускается снова.

```bash
sudo /opt/pi-agent-kit/deploy/pi-kit backup
sudo /opt/pi-agent-kit/deploy/pi-kit update
sudo /opt/pi-agent-kit/deploy/pi-kit rollback
sudo /opt/pi-agent-kit/deploy/pi-kit restore /var/backups/pi-agent-kit/latest.tar.gz
```

Обновление сначала делает копию, устанавливает зависимости и запускает тесты
в отдельной папке, затем ненадолго останавливает службу и заменяет код.
Секреты, память, задания и авторизация сохраняются. Предыдущий код с зависимостями
остаётся в `/opt/pi-agent-kit.previous`; `rollback` возвращает его, сохраняя
текущие данные. Можно указать версию: `update <tag-или-commit>`.

Если помощник или вы изменили исходники, обновление откажется их затирать.
Обновление и откат также останавливаются при локальных коммитах, отсутствующих
в refs `origin`. Сначала сделайте `backup`, сохраните свою ветку, обновите refs
`origin` и согласуйте правки с upstream вручную. Помощник может помочь
согласовать изменения; коммит сохраняет историю правок, но автоматическая
замена кода требует, чтобы текущая история уже присутствовала в `origin`.

`restore` восстанавливает данные из архива для этой же установки: зависимости
готовятся заранее, служба останавливается **до** замены действующих данных.
Текущая папка остаётся в `.previous`, предыдущая внешняя память — в соседней
папке `*.before-restore-*`. Эти аварийные папки не входят в ротацию архивов.
При переносе на новый сервер сначала сохраните те же пути и владельца файлов.
Архив содержит ключи; не публикуйте его.

Для внешнего диска задайте `PI_KIT_BACKUP_DIR=/путь/к/копиям` при установке.
Он должен находиться вне исходников и памяти. В существующей установке путь
хранится в `.deployment.json`.

## Обслуживание

```bash
sudo systemctl status pi-agent-kit
sudo journalctl -u pi-agent-kit -f
sudo systemctl restart pi-agent-kit
sudo systemctl stop pi-agent-kit
sudo systemctl list-timers pi-agent-kit-backup.timer
cd /opt/pi-agent-kit
sudo -u pi-agent-kit /opt/pi-kit-node/bin/node scripts/doctor.mjs
```

Если подходящий Node уже был установлен, используйте его путь вместо
`/opt/pi-kit-node/bin/node`. `doctor` проверяет локальные настройки;
ответ в Telegram проверяет доступ к модели. Ошибка Telegram 409 обычно означает
второй экземпляр бота или webhook. Ошибку модели проверьте по балансу, ключу
и `pi.provider`/`pi.model`. Не запускайте второй polling-процесс параллельно службе.

Для старой установки без `.git`: сделайте `backup`, вручную согласуйте исходники
с выбранной версией, затем `adopt [version]`. Команда сравнивает каждый файл
и добавляет Git только при совпадении; личные данные сохраняются.
Существующая папка памяти никогда не должна заменяться новым шаблоном.

## Локальный запуск и разработка

На машине с Node.js **22.19+**:

```bash
git clone https://github.com/Hamyrappy/pi-agent-kit.git
cd pi-agent-kit
npm ci --ignore-scripts
npm run init
# добавьте OPENROUTER_API_KEY в .env и выберите provider/model в config
npm run model:configure
npm run doctor
npm start
```

Для OAuth вместо API key: `npm run login`, затем Pi `/login` и `/model`.
Вход и запуск используют одну папку `.pi-agent/`; если переопределяете
`PI_CODING_AGENT_DIR`, задавайте её одинаково для обеих команд.
Для user-service после настройки: `npm run service:install`; для работы
после выхода пользователя может понадобиться `loginctl enable-linger "$USER"`.
Локальный `init` читает токен видимо; серверный установщик скрывает ввод.

`npm test` использует временные папки и поддельные Telegram/Pi endpoints.
Рендер Markdown находится в `src/markdown.mjs`, его тесты — в `tests/markdown.test.mjs`.
Зависимость Pi зафиксирована в `package-lock.json`. Обновляйте её вместе с тестами.
Ни секреты, ни `vault/`, ни состояние не входят в Git. Лицензия MIT.

Для автоматической установки передайте переменные через `sudo env`:
`PI_KIT_NONINTERACTIVE=1`, `PI_KIT_BOT_TOKEN`, `PI_KIT_OWNER_ID`,
`PI_KIT_OPENROUTER_KEY`, необязательно `PI_KIT_BOT_NAME`, `PI_KIT_TIMEZONE`,
`PI_KIT_MODEL`, `PI_KIT_ROOT`, `PI_KIT_USER`, `PI_KIT_SERVICE`,
`PI_KIT_BACKUP_DIR`, `PI_KIT_VERSION`. Секреты безопаснее передавать через
закрытый environment-файл, а не записывать в историю shell.
